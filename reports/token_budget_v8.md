# L4 MMMU — 출력 토큰 한도별 V8 절단 분석

작성일: 2026-09-30 · 원본 실행: `mmmu-l4-full-01-evaluation`

**저장된 900개 응답의 앞부분만 남겨 같은 V8로 재채점했다. 2,048토큰에서는 485/900 = 53.89%, 8,192에서는 552/900 = 61.33%다.**
이는 이미 생성된 답변의 절단 분석이며, 각 토큰 한도로 모델을 새로 실행한 결과가 아니다.
기존 baseline **564/900 = 62.67%**와 원본 응답·V8 소스는 보존한다.

## 방법과 검증

- 모델은 기존 `Qwen/Qwen3-VL-4B-Instruct` @ `ebb281ec70b05090aa6165b016eac8ec08e71b17`이다. 추가 학습·GPU 추론을 수행하지 않았다.
- 실제 보존된 `generated_token_ids`의 앞 `min(한도, 원래 길이)`개를 디코딩했다. 문자 수로 자르거나 텍스트를 재토큰화하지 않았다.
- 동일 revision의 `tokenizer.json`에서 ByteLevel 디코딩을 적용했다. 특수 토큰 제외, 공백 정리 없음, UTF-8 오류 대체 정책을 유지했다. **원래 전체 토큰을 디코딩한 900개 모두 저장된 `raw_response`와 정확히 일치**했다.
- 보존된 V8 및 의존 소스 4개의 SHA-256을 검증했다. scorer hash는 `b80a28a4b66906d5c4f1ece046bd7c4be2b447445da4b072144e52ce7ee047fa`다.
- 절단 전에는 900개 모두 추출 답·상태·정오·추출 규칙·근거·추출 상태가 원래 기록과 일치했다. 정답 564개와 `NO_PARSE` 87개를 재현했다.
- 원래 길이가 한도 이내인 응답은 그대로 사용했다. 절단한 응답의 종료 표시는 분석상 `length`로 두었지만, **V8은 `finish_reason`을 무시하고 보이는 텍스트로 답을 추출**한다.
- 각 한도의 분모는 900이다. 원본 900개 파일의 SHA-256이 분석 전후 동일함을 확인했다.
- 512·4,096·8,192에서는 각각 1개씩 절단된 텍스트가 UTF-8 오류 대체 문자로 끝났다. 2,048에서는 없었다. 해당 건수는 JSON의 `partial_utf8_endings`에 보존했다.

## 한도별 결과

‘정답 잃음 / 얻음’은 원래 32,768토큰 결과와 같은 문항끼리 비교한 값이다.

|---:|---:|---:|---:|---:|---:|---:|---:|
| 512 | 360 | 40.00% | 399 | 423 | 204 / 0 | 336,118 | 91.24% |
| 2,048 | 485 | 53.89% | 222 | 225 | 79 / 0 | 776,984 | 79.75% |
| 4,096 | 524 | 58.22% | 163 | 170 | 41 / 1 | 1,179,467 | 69.26% |
| 8,192 | 552 | 61.33% | 110 | 110 | 12 / 0 | 1,739,949 | 54.65% |
| 32,768 — 원본 검증 | 564 | 62.67% | 87 | 0 | 0 / 0 | 3,836,776 | 0.00% |

이 표는 남긴 출력 토큰의 양을 측정한다. **시간·GPU 비용·메모리가 같은 비율로 감소했다는 측정은 아니다.**
2,048→4,096에서는 정답이 순증 39개, 4,096→8,192에서는 순증 28개, 8,192→32,768에서는 순증 12개다.

## 2,048에서 어떤 답을 잃었나

원래 2,048토큰 이내에 끝난 **675개**는 그대로이며, 그중 정답은 **478개**다.
길이가 2,048을 넘는 **225개** 중 원래 정답 86개 가운데 **7개는 앞부분의 답이 추출되어 정답을 유지**했다.
나머지 **79개는 정답을 잃었다: 77개는 NO_PARSE, 2개는 다른 답으로 추출**됐다.
원래 오답에서 정답으로 바뀐 문항은 없다.

| 원래 결과 → 절단 후 결과 | 정답 | 추출 후 오답 | NO_PARSE |
|---|---:|---:|---:|
| 정답 | 485 | 2 | 77 |
| 추출 후 오답 | 0 | 190 | 59 |
| NO_PARSE | 0 | 1 | 86 |

| `validation_Math_8` | 2,048 | 풀이 중 꼭짓점 목록의 D에서 잘림. V8의 `terminal:label` 규칙이 이를 선택지 D로 읽음. 전체 응답의 최종 답은 B |

이 사례 해석은 AI 어시스턴트의 원문 검토이며 독립적인 사람 전문가 검수는 아니다.
특히 Math 8은 모델이 D를 최종 답으로 선택했다고 해석하면 안 된다. **절단으로 생긴 마지막 줄을 파서가 답으로 읽은 것**이다.
Physics 12의 채점상 개선 역시 짧게 새로 추론했을 때의 성능 향상을 측정한 것이 아니다.
파서 규칙이나 문항별 예외를 추가하지 않았다.

## 과제 권장값과 해석

수업 자료 `02_MMDL_Team_Project_Introduction.pdf` 16쪽의 **Inference Setup**은 RTX 4090 권장 설정으로
`max_new_tokens=2048`, `max_model_length=9048`을 제시한다. 슬라이드 표현은 필수 고정값이 아닌 권장 설정이다.
해당 수업 자료는 저장소에 재배포하지 않는다.

기존 실행은 출력 한도 32,768, 전체 컨텍스트 40,960이었다. 이번 분석은 그 응답의 출력만 잘랐으므로,
**2,048 행을 과제의 전체 권장 설정으로 실제 재실행한 점수라고 부를 수 없다.**
모델·프롬프트·이미지 처리·생성된 앞부분의 토큰을 모두 고정한 사후 분석이다.

출력 한도는 생성을 멈추는 조건이다. 이번 실험에서는 같은 생성 결과의 앞부분을 정확히 고정했지만,
새 GPU 실행에서 배치 구성·난수 소비·수치 연산 조건까지 같다고 가정할 수는 없다.
[vLLM 0.11.1 재현성 문서](https://docs.vllm.ai/en/v0.11.1/usage/reproducibility/)도 실행 환경 조건을 설명한다.
이 링크는 인접 버전의 참고 문서이며, 원래 실행의 vLLM 버전은 0.11.0이다.

**8,192는 다음 실제 추론으로 검증할 후보**다. 저장 응답에서는 원본 대비 정답 12개(1.33%p)를 잃고 출력 토큰은 54.65% 줄었다.
최적 한도나 새 실행의 점수를 확정한 것은 아니다. 실제 비교 시에는 동일 문항·시드·프롬프트·이미지 설정과 전체 컨텍스트를 유지하고 출력 한도만 바꿔야 한다.
과제의 전체 권장 설정을 재현하는 실행은 별도로 기록한다.

## CPU 재현 방법

복원한 원본 `artifacts/`와 고정 tokenizer가 필요하다. **공개 저장소만으로는 원문이 없으므로 재채점을 실행할 수 없다.**
스크립트는 원래 `runs/mmmu-l4-full-01-evaluation/samples/`와
`rescores/mmmu-l4-full-01-v8-07b867b5bfae/scorer_source/` 및 `scorer_source.json`을 읽는다.
Python 3.12와 원래 채점기 의존성 환경을 사용한다. 새 패키지나 모델 가중치를 설치·다운로드하지 않는다.

고정 토크나이저가 없는 경우, 아래 작은 메타데이터 파일만 별도로 받는다:

```bash
curl --fail --location \
  https://huggingface.co/Qwen/Qwen3-VL-4B-Instruct/resolve/ebb281ec70b05090aa6165b016eac8ec08e71b17/tokenizer.json \
  --output /tmp/qwen3-vl-4b-tokenizer.json
```

복원 경로를 지정하고 새 출력 파일을 사용한다:

```bash
python3 scripts/analyze_token_budget.py \
  --artifacts /path/to/restored/artifacts \
  --tokenizer /tmp/qwen3-vl-4b-tokenizer.json \
  --output /tmp/mmmu-token-budget-v8-summary.json
```

토크나이저 SHA-256과 채점 소스 hash, 원본 디코딩·채점 일치를 모두 통과해야 집계를 출력한다.
검증을 비활성화하는 `python -O`는 거부한다. 기존 출력 파일과 보존된 artifacts 내부에는 쓰지 않는다.
출력 JSON에는 집계·출처·파일 hash만 담으며, 문제·보기·원문 응답·생성 토큰 ID·인증정보·호스트 절대경로를 담지 않는다.
로컬의 원문 포함 HTML·문항별 JSONL은 Git 반영 대상에서 제외한다.
