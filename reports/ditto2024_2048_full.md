# DITTO2024 테스트 결과 — MMMU 900문항, 2,048토큰

작성일: 2026-10-11 · 팀 공유용 실험 결과 · 공학 중심 210문항의 저장된 풀이 검토 추가

## 논문 한눈에 보기

[**Show, Don’t Tell: Aligning Language Models with Demonstrated Feedback (2024)**](https://arxiv.org/html/2406.00888v1)은 **소수의 좋은 응답 예시로 모델의 답변 방식·문체를 원하는 방향에 맞추는 방법**을 제안한다. 방법 이름은 **DITTO (Demonstration ITerated Task Optimization)**다.

- **학습 방법:** 시범 응답으로 짧게 SFT한 뒤, 같은 질문에 모델이 직접 응답을 생성한다. 시범 응답을 생성 응답보다 선호하는 비교 쌍을 만들고 **DPO로 그 선호를 학습**한다. 이를 반복하면서 이전 모델의 응답도 비교에 사용한다.
- **핵심 가정:** 시범 응답을 우선하고, 모델끼리는 더 최근 정책의 응답을 우선한다. 이는 학습용 선호 규칙이며, **최근 응답이 매번 더 정확하다고 검사한 결과는 아니다.**
- **원 논문의 실험:** 주로 Mistral 7B에서 이메일·블로그·기사 등의 문체와 사용자 선호를 맞추는 능력을 평가했다. **공학 문제의 풀이 정확도나 토큰 절감을 직접 입증한 논문은 아니다.** [논문 방법·실험](https://arxiv.org/html/2406.00888v1#S3)

**우리의 적용:** 좋은 응답 예시 자리에 **ScienceQA 8문항의 해설과 최종 답**을 넣고 Qwen3-VL에 적용했다. 즉, “설명하고 답을 마무리하는 시범”을 학습하면 MMMU 풀이도 좋아지는지 시험한 것이다. 아래 결과는 이 소규모 응용 테스트의 결과이며, 원 논문의 성능을 그대로 재현한 결과는 아니다.

## 결론

**일부 문항의 풀이와 최종 답은 개선됐지만, 이번 설정에서 전체 정확도 향상이나 토큰 절감은 확인되지 않았다.**

- 전체 정답은 **479/900 → 472/900**으로 7개 감소했다. 새로 맞힌 39개와 새로 틀린 46개가 함께 발생했다.
- 기존에 선정한 기술·공학 중심 7분야 210문항은 **57/210 → 57/210**으로 같았다. 내부적으로는 13개 개선·13개 악화였다.
- 평균 출력은 **866.9 → 876.2토큰**으로 소폭 늘었다. 2,048토큰 상한 도달과 최종 답 추출 실패도 줄지 않았다.

이번 실험은 **본격적인 학습 확대 전의 소규모 가능성 테스트**다. 실제 LoRA 가중치 업데이트는 수행했으나, 이 결과만으로 DITTO2024 전체가 효과 없다고 결론 내리거나 점수 차이를 학습만의 효과로 단정할 수는 없다. 평가 파서는 양쪽 모두 기존 고정 V8을 그대로 사용했고, 사후 점수 보정은 하지 않았다.

## 1. 무엇을 테스트했나

대상은 [Show, Don’t Tell: Aligning Language Models with Demonstrated Feedback (2024)](https://arxiv.org/abs/2406.00888)의 DITTO 방식이다. 이전에 실험한 **반복 억제 목적의 DITTO2022와는 다른 방법**이다. 원 논문의 텍스트 정렬 방식을 Qwen 멀티모달 모델에 응용한 시험이며, 원 논문 성적의 직접 재현은 아니다.

| 항목 | 이번 설정 |
|---|---|
| 모델 | Qwen3-VL-4B-Instruct |
| 학습 자료 | ScienceQA 공식 train에서 선택한 이미지·질문·정답 풀이 **8문항** |
| 공통 시작점 | SFT warmup **4 업데이트** |
| DITTO 학습 | 고정 warmup 참조 모델에 대한 DPO **2라운드 × 10 = 20 업데이트** |
| 학습 범위 | LoRA rank 8, alpha 16, dropout 0; 언어모델 q/k/v/o projection, 비전 부분 고정 |
| 선호 자료 | 32개 모델 응답 생성(각 512토큰 상한), 라운드별 20쌍; 총 40쌍 |
| 선호 순서 | 전문가 시범 > 생성 응답, 새 정책 응답 > 이전 정책 응답. 정답 여부로 필터링하지 않음 |
| 평가 | MMMU validation 전체 **900문항**, 분야별 30문항, 출력 상한 **2,048토큰** |
| 실행 | NVIDIA L4, vLLM 0.11.0, engine seed 3407, 문항별 seed, multiprocessing 비활성화 |
| 비교 대상 | 기존 학습 전 2,048토큰 실제 생성 결과 **479/900** |
| 채점 | 동일한 `team-final-answer-v8`, 원문에서 독립 재채점 |

DPO는 선호하는 응답을 상대적으로 더 생성하도록 학습하는 방법이다. 여기서 비선호 응답이 모두 오답이라는 뜻은 아니다. 본 평가에서는 `ditto2024-pilot-02`의 학습 완료 가중치를 재사용했고 **추가 학습 없이 900문항만 생성·평가**했다. 원본 전처리 설정을 유지한 완료 실행 `ditto2024-2048-full-02-evaluation`의 결과를 사용했다.

학습 8문항과 MMMU900의 기존 정확 일치 중복 검사는 0건이었다. 의미가 비슷한 변형 문제나 Qwen 사전학습 데이터와의 중복까지 배제한 것은 아니다.

### 학습 타깃은 “풀이과정을 쓰는 것”이었나?

**맞다. 이번 적용에서 유도한 행동은 “근거를 설명하고 문제에 적용한 뒤 최종 답을 쓰는 응답”이었다.** 다만 긴 풀이를 많이 쓰거나 추론 단계를 하나씩 검증하도록 만든 별도 목적 함수는 없었다. [원 논문](https://arxiv.org/html/2406.00888v1)은 소수 시범으로 원하는 행동·문체에 맞추는 방법이며, 풀이 정확도 개선 자체를 전제로 한 방법은 아니다. 우리는 그 시범 자리에 ScienceQA 해설을 넣었다.

실제 학습 원본 8개에는 모두 설명과 `Final answer:`가 있다. 예를 들어 자석 문제(ID `1548`)의 타깃은 다음 내용이다. 아래는 원문을 한국어로 요약한 것이다.

> 자석 사이 거리가 멀수록 자기력이 약하다 → 그림에서 Pair 2의 거리가 더 멀다 → 따라서 Pair 2의 힘이 더 작다 → 최종 답 B.

학습은 다음 두 단계로 이 응답을 유도했다.

1. **SFT warmup 4회:** 질문·이미지 다음에 나오는 **설명부터 최종 답까지 전체 응답 토큰**을 맞히도록 학습했다. 답 알파벳만을 타깃으로 쓰지 않았다.
2. **DITTO의 DPO 20회:** 같은 문제의 시범 해설을 모델 생성 응답보다 선호하도록 응답 전체의 상대적 확률을 학습했다. 일부 쌍에는 새 정책 응답 > 이전 정책 응답이라는 규칙도 적용했다. 각 풀이 단계의 정오를 별도로 라벨링하거나 보상하지 않았다.

시범 타깃은 종료 토큰 포함 **73~238토큰, 평균 100토큰**이었다. 긴 CoT, 토큰 축소, 반복 억제 중 어느 것도 독립된 보상 항목으로 넣지 않았다. 시범 응답의 내용·표현·종료 방식이 함께 학습 신호가 되었으므로, 그중 어떤 요소를 얼마나 배웠는지는 따로 확인해야 한다. 학습 전 모델도 이미 풀이를 쓰는 사례가 있었기 때문에, 풀이가 존재한다는 사실만으로 이번 학습의 효과라고 판단할 수 없다.

### 그 타깃을 실제로 배웠는지는 어디까지 확인했나?

| 확인할 질문 | 이번 근거 | 판단 |
|---|---|---|
| 가중치 업데이트가 실제로 일어났나? | DPO 20회 완료, 모든 loss·gradient 유한, gradient 0 아님, 시작 가중치 대비 adapter L2 변화 0.03514, 참조 불변·저장 모델 재로딩 검증 | **실행과 실제 업데이트는 확인** |
| 설명·최종 답 형식을 더 일관되게 쓰나? | 900문항의 풀이 존재율을 사전 정의된 기준으로 전수 평가하지 않음. 시범의 `Final answer:` 문자열 관측 응답도 320→307개 | **형식 습득·개선은 입증하지 못함** |
| 풀이 내용이 더 정확해졌나? | 공학 중심 210문항의 전후 원문을 검토. 빠뜨린 제약·단면적 계산을 바로잡은 사례와 회로 해석 오류·미완결 사례가 함께 관측됨 | **실제 개선 사례는 있으나 일관된 품질 향상은 확인하지 못함** |
| 문제를 더 잘 맞히나? | 같은 V8 기준 479→472개, 공학 중심 57→57개 | **이번 실행에서 총점 향상 없음** |

문자열 관측은 응답에서 굵게 표시(`**`)와 backtick을 제거한 후 대소문자 구분 없이 `final\s+answer\s*:`가 한 번이라도 나타나는지 센 값이다. 문장 끝에 있는지, 답이 맞는지, 풀이가 타당한지를 평가한 지표가 아니며 **기존 V8 점수에는 반영하지 않았다.** 이 문자열이 없다고 풀이를 쓰지 않았다는 뜻도 아니다.

학습 로그의 라운드별 배치 평균 loss는 0.69877→0.68657이었다. 하지만 두 라운드는 비교 쌍과 생성 응답이 다르고, 최종 모델의 고정 평가 세트 결과도 아니다. 이 감소만으로 풀이 능력을 배웠다고 주장할 수 없다.

따라서 이번 결론은 **“풀이를 포함한 시범 응답으로 실제 학습은 수행했고, 핵심 계산이 좋아진 사례도 있다. 하지만 공학 중심 210문항의 저장된 설명을 검토했을 때 일관된 품질 향상은 확인하지 못했고, 최종 정답률도 늘지 않았다”**이다. “풀이를 학습시키지 않았다” 또는 “풀이 학습 자체가 효과 없다”는 결론은 이 실험으로 내릴 수 없다. 아래 사후 검토에서는 **설명 유무 → 핵심 단계의 타당성 → 최종 답과의 일치 → 제한 내 완결 여부**를 구분했다. 후속 실험에서는 같은 추론 조건의 base·SFT-only·DITTO를 이 기준으로 비교해야 한다.

## 4. 저장된 풀이 검토: 실제 개선과 분량 변화를 구분하면

**잘못된 계산·누락된 조건을 고친 사례는 있다. 그러나 길어진 설명이 더 정확한 풀이를 뜻하지 않았고, 맞는 접근을 놓치거나 답을 끝내지 못한 사례도 있었다.** 따라서 이번 테스트를 “풀이를 더 잘 쓰도록 학습하는 데 성공했다”고 묶어서 보고하기는 어렵다.

### 검토 범위와 기준

기존 7분야 **210문항의 학습 전후 응답 420개**를 읽고, 핵심 조건·공식·계산과 최종 답의 연결을 검토했다. 그중 **115문항은 이미지도 직접 확인**했고, 데이터셋 해설이 제공된 문항은 **43개**였다. 이는 **AI 보조 사후 검토이며 독립 전공 전문가의 이중 판정은 아니다.** 모든 문제를 완전히 독립 해결한 것은 아니며, 도면·정답 해설·물성 조건이 불명확한 사례는 개선 근거로 삼지 않았다. 관찰 대상도 모델이 출력한 설명이지, 내부 추론 과정 자체는 아니다.

| 공학 중심 210문항의 관측 | 학습 전 | DITTO2024 |
|---|---:|---:|
| 기존 V8 정답 | 57 | 57 |
| 평균 생성 토큰 | 1,416.8 | 1,425.8 |
| 2,048토큰 상한 도달 | 116 | 118 |

전후 비교에서 **50개는 길어지고, 42개는 짧아지고, 118개는 토큰 수가 같았다.** 같은 길이 중 103개는 양쪽 모두 상한에서 끝났으므로, 길이가 같다고 내용까지 같거나 효율이 같다는 뜻은 아니다. 실제 원문까지 완전히 동일한 것은 14개였다. 아래 사례의 정오 표기는 모두 **기존 V8 채점 결과**이며, 내용 검토로 점수를 수정하지 않았다. ID의 `validation_` 접두사는 생략했다.

### A. 핵심 풀이가 실제로 좋아진 사례

**Computer_Science_9 — 빠뜨린 병목 제약을 반영**

- 전: 마지막 수신 링크의 60 Mbps 제약을 빼고 **75 Mbps**로 답했다.
- 후: 경로 전송률을 `min(80, 300/4, 60)=60 Mbps`로 계산해 **60 Mbps**로 마무리했다.
- **오답→정답, 681→936토큰.** 단순히 답 표현이 달라진 것이 아니라 필요한 조건을 포함한 개선이다. 다만 더 길어졌고 병목을 재확인하는 설명도 남았다.

**Computer_Science_22 — 빈 문자열을 허용하는지 바로 판단**

- 전: NFA가 빈 문자열도 받아들인다고 해석해 `a* 또는 b*`에 해당하는 **D**를 골랐다.
- 후: 받아들여지려면 최소 한 개의 `a` 또는 `b`를 읽어야 함을 반영해 `aa* 또는 bb*`인 **A**를 골랐다.
- **오답→정답, 566→1,434토큰.** 언어의 최소 길이라는 핵심 조건을 바로잡았다. 같은 조건을 여러 번 확인하는 부분까지 효율이 좋아진 것은 아니다.

**Materials_5 — 봉의 단면적 오류를 고치고 최종 질량까지 연결**

- 전: 샹들리에를 지탱하는 봉의 평형식은 맞게 세웠지만, 원형 단면적에서 반지름 제곱을 잘못 계산했다. AB 허용력을 약 **707 N**, 질량을 약 **98 kg**으로 얻고 결론을 내지 못했다.
- 후: `A=πd²/4`를 정확히 적용해 AB 허용력 약 **1,060 N**을 구했다. 두 봉의 제한을 비교해 지배하는 AB를 기준으로 질량 약 **147.6 kg → B, 148 kg**까지 이어졌다.
- **추출 실패→정답, 2,048→1,522토큰.** 계산 오류 수정과 제한 내 완결이 함께 개선된 사례다.

### B. 더 길어졌지만 풀이 개선으로 볼 수 없는 사례

**Computer_Science_23 — 풀이 개선보다 답 추출 차이**

- 첫 RTT 추정값 `0.875×250+0.125×280=253.75 ms`는 **양쪽 모두 이미 정확히 계산하고 원문에 답으로 명시**했다.
- 기존 V8은 전 응답에서 답을 추출하지 못하고, 후 응답에서는 `253.75`를 추출했다. 두 응답에는 질문에 필요 없는 뒤쪽 RTT 업데이트의 산술 오류도 남았다.
- **채점상 오답→정답, 1,148→1,254토큰.** 점수는 올랐지만 이 문항을 새로운 풀이 능력의 근거로 세면 안 된다.

**Electronics_2 — 같은 실효값 계산에 반복 확인이 늘어남**

- 제공된 한 파형의 진폭은 4 A다. 양쪽 모두 `Irms=4/√2=2√2≈2.83 A`를 올바르게 계산하고 수학적으로 맞는 최종 값을 썼다.
- 후 응답은 주기가 4 ms인지 여러 차례 확인하고 적분도 덧붙였다. **505→1,967토큰, 약 3.9배**가 됐지만 새 오류를 고친 것은 아니다.
- **V8 점수는 양쪽 모두 오답**이다. 전에는 추출 실패, 후에는 답 대신 설명 문구가 추출됐다. 질문에는 세 파형이라고 쓰였지만 제공 이미지에는 하나만 있어, 검토는 그 파형에 한정한다.

**Electronics_5 — 설명이 늘어도 지배적인 회로 모델 오류는 유지**

- 이미터 팔로어의 출력 저항은 소스 저항이 이미터 쪽으로 반영되는 항을 포함하면 약 **62.61 Ω**이다: `5,600 Ω ∥ [50 Ω + (680 Ω ∥ 470,000 Ω)/51]`.
- 양쪽 모두 이 항을 빠뜨려 원문에서 약 **50 Ω**이라고 결론냈다. 후 응답이 작은 분모 표기 오류는 고쳤지만, 출력 단락·입력 개방이라는 잘못된 설명도 추가했다.
- **804→1,306토큰, 채점상 계속 오답**이다. 후 응답은 V8에서 추출되지도 않았다. 설명의 양이나 작은 산술 수정만으로 핵심 풀이가 개선됐다고 볼 수 없다.

### C. 풀이가 나빠지거나 최종 답으로 이어지지 못한 사례

**Mechanical_Engineering_14 — 맞는 에너지 접근을 끝내지 못함**

- 전에는 질량과 드럼의 운동에너지, 추가 정지 토크를 모두 계산하고 **A**를 선택했다.
- 후에도 에너지 공식은 맞게 세웠으나 선택지와의 수치 차이를 반복 검토하다 토크 계산과 최종 선택 전에 상한에 도달했다.
- **정답→추출 실패, 1,674→2,048토큰.** 독립 계산 약 9,684.91 J·2,219.46 N·m와 선택지 A의 9,673 J·2,218 N·m에는 실제 차이가 있다. 따라서 재검토 자체를 전부 쓸모없다고 보거나 차이를 단순 반올림이라고 처리하지 않았다. 확인된 악화는 요구된 두 답을 제한 내 완결하지 못한 것이다.

**Electronics_10 — 점수는 같아도 회로 해석은 악화**

- 그림은 R–C 직렬 가지와 R–L 직렬 가지가 전원에 병렬로 연결된 회로다. 요청된 전류는 `I1=100/(100−j265.3)≈0.12444+j0.33008 A`로 구할 수 있다.
- 전에는 가지의 직렬 임피던스를 맞게 세웠으나 불필요한 전체 등가 계산과 산술 오류로 미완결됐다. 후에는 **가지 안의 직렬 소자까지 병렬로 해석**해 출발 모델 자체가 틀렸다.
- **양쪽 모두 2,048토큰·추출 실패.** 최종 정오만 비교하면 보이지 않는 풀이의 악화다.

**Energy_and_Power_11 — 짧고 정답이어도 설명 전체가 맞지는 않음**

- 양쪽 모두 단열 팽창에서 `Q=0`, `ΔT<0`을 연결해 **B**로 답했다. 전 응답의 초기 일 부호 혼동은 뒤에서 스스로 정정됐다.
- 후에는 **1,260→385토큰**으로 짧아졌지만, `Q=0`인 보기 C를 `Q≠0`이라고 제거하는 오류가 남았다. 상태 1의 부피가 더 크다는 설명도 뒤의 팽창 설명과 충돌했다.
- **계속 정답**이지만 완전히 정확하고 간결한 풀이로 개선됐다고 판정할 수 없다. 상태 좌표 이미지는 이 검토에서 재확인하지 않았으며, 해당 지적은 출력 텍스트·선택지 사이의 모순에 한정한다.

### 학습 목표에 대한 해석

이번 시범 학습은 **설명부터 최종 답까지 전체 응답을 선호하도록** 했지만, 단계별 정확도·불필요한 재검산·최종 답 완결을 각각 보상한 것은 아니다. 관측 결과도 그 구분을 보여 준다. 빠뜨린 조건과 계산을 고친 응답은 있는 반면, 설명만 길어지거나 잘못된 회로 설명을 확장한 응답도 있다.

**팀에 전달할 결론은 “국소적인 풀이 개선은 확인했지만, 공학 분야 전반의 정확한 풀이와 완결성이 좋아졌다는 근거는 부족하다”이다.** 길이 감소만을 성공으로 세지 않고, 핵심 풀이의 타당성과 최종 답으로의 연결을 함께 봐야 한다. 이 변화가 학습만으로 발생했는지는 6절의 추론 조건 차이와 SFT 대조군 부재 때문에 분리할 수 없다.

공유 JSON의 `engineering_reasoning_review`에는 검토 범위·집계와 위 **9개 대표 사례**의 전후 답, 파싱·토큰·종료 상태, 검토 설명, 원문 해시를 담았다. 기존 900문항 대표 검토는 `manual_review_findings`에 별도로 보존했다. 대표 사례는 설명을 위한 사후 선정이며, 9개의 비율을 전체 개선율로 해석하지 않는다.

## 5. 실패를 어떻게 해석하나

DITTO2024에서 오답 처리된 **428문항**은 다음과 같다.

| 관측된 상태 | 수 |
|---|---:|
| 2,048토큰 상한 도달 + 최종 답 추출 실패 | 229 |
| 상한 도달 없이 최종 답 추출 실패 | 14 |
| 답은 추출됐지만 정답과 불일치 | 185 |

새로 틀린 46개 중 33개는 `NO_PARSE`, 13개는 추출된 답이 틀린 경우였다. 새로 맞힌 39개 중 20개는 기존 `NO_PARSE`에서 답이 추출된 경우, 19개는 양쪽 모두 답은 추출되지만 정오가 바뀐 경우였다.

따라서 **답을 끝까지 확정해 내는 능력이 개선됐다는 근거는 부족**하다. 대표 원문에는 근거 없는 추가 가정, 그래프 오독, 선택지와 수치가 조금 다를 때 과도하게 재검산하는 모습도 있었다. 반면 제한 조건을 새로 반영해 맞힌 사례도 있어 단일 원인으로 설명하기 어렵다.

`NO_PARSE`는 실행 실패나 풀이 전체의 오류와 같은 말이 아니다. 실제 실행 실패는 0건이다. 예를 들어 Math_15는 양쪽 모두 올바른 `24/7`을 계산했지만 분수 표현이 고정 V8에서 추출되지 않았다. **파서는 수정하지 않고 양쪽에 동일하게 적용한 점수를 유지했다.**

## 6. 학습 효과에 대해 말할 수 있는 범위

확인된 사실은 **이 소규모 가중치 업데이트를 적용한 실행에서 응답이 달라졌고, 일부 문제의 핵심 풀이가 나아졌지만 전체 성적·출력량은 개선되지 않았다는 것**이다. 다음 이유로 “DPO만의 효과”는 아직 분리되지 않았다.

1. **학습 전 실행과 추론 조건 차이:** 기존 479점 실행에는 명시적 engine seed와 multiprocessing 비활성화가 없었다. 이번 실행은 seed 3407·MP0을 사용했다. seed 고정만으로 전체 재현성이나 배치 불변성이 입증되지는 않으며, vLLM 0.11.0은 `VLLM_BATCH_INVARIANT`를 지원하지 않는다.
2. **900문항 SFT 대조군 부재:** 이번 결과는 공통 SFT warmup과 DPO를 거친 모델이다. 동일한 900문항의 SFT-only 결과가 없어 풀이 시범을 보여 준 효과와 DPO의 추가 효과를 분리할 수 없다. 21문항 SFT 비교만으로 이를 대체할 수 없다.
3. **소규모·탐색 실험:** 학습 시범 8개와 DPO 20 업데이트이며, 기존 개발용 문항도 평가에 포함된다. 분야별 표본이 30개이고 여러 분야를 함께 비교했으므로 일부 분야의 상승을 일반화하기 어렵다.
4. **선호 순서와 정답은 다름:** 전문가/새 정책 우선이라는 규칙으로 쌍을 만들었고, 비선호 응답을 오답으로 걸러내지 않았다. 선호학습이 곧바로 시험 정답률 개선을 보장하는 구성은 아니다.

학습량이 작거나 선호 자료와 목표 과제가 맞지 않아 효과가 제한됐을 가능성은 **가설**이다. 이번 자료로 그 원인을 확정할 수는 없다.

본 테스트는 여기서 마무리한다. 후속 실험을 한다면 **같은 추론 조건에서 base·SFT-only·DITTO2024를 비교**하고, 기존에 보지 않은 고정 평가 표본에서 최종 정답과 핵심 풀이 타당성을 함께 확인하는 것이 우선이다. 이번 정리 과정에서 추가 학습이나 재평가는 실행하지 않았다.

## 7. 검증·소요 시간·보존

- **완전성:** 동일한 900개 고유 ID, 누락 0·중복 0·실행 실패 0. 입력 SHA256, 실제 prompt token ID, 이미지 grid와 처리 크기는 900개 모두 일치했다. 엔진 내부 pixel tensor 바이트 일치까지 확인한 것은 아니다.
- **채점:** 원본 `validate_run` 통과. 고정 V8로 원문을 독립 재채점했으며 저장된 채점 결과와 불일치 0건이다.
- **회수:** Drive 증분 ZIP/ready **915쌍**을 순서대로 SHA256·CRC 검증했다. CPU에서 전체 2,828개 artifact를 복원했으며, 로컬로 회수한 텍스트 artifact 1,865개도 해시 검증했다. 원본 백업은 보존돼 있고 마지막 ZIP 하나만으로 복구할 수 없다.
- **시간:** 이번 900문항 평가 기록은 **5시간 40분 35초**, 해당 invocation 전체는 **5시간 42분 11초**였다. 과거 학습 시간이나 인증·복구 대기는 포함하지 않는다.
- **사용량:** CU 잔액 21.45→9.14, 차이 12.31 CU는 관측값이다. 준비·대기와 이후 사용까지 섞여 있어 **평가만의 정확한 CU 비용으로 사용할 수 없다**. 종료 후 활성 세션 0과 요율 0을 확인했다.

공유 JSON에는 집계, 900개 그룹별 ID, 정오가 바뀐 85문항의 전후 답·토큰·파싱·종료 상태, 기존 대표 풀이 검토, 공학 중심 210문항 검토의 범위·집계와 대표 9개 사례, 근거 파일 해시를 담았다. 모델 가중치·문항 이미지·900개 전체 응답 원문은 이 게시물에 포함하지 않았으므로 JSON만으로 원문 재채점을 전부 재현할 수는 없다.
