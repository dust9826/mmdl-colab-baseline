# 고정 마무리 SFT · 프로젝트 미사용 MMMU test 900문항

실제 평가: 2026-11-19 KST · 문서 갱신: 2026-11-20 · 동일 보존 가중치·L4·자유 생성 2,048토큰·고정 V8

## 먼저 읽을 결론

**별도 test 900개에서 원본 476/900 → 마무리 SFT 470/900으로, 전체 성능 향상을 확인하지 못했다.** 기술·공학 210개는 48→56개로 늘었지만 나머지 690개가 428→414개로 줄었다. 기존 validation의 487점을 새로 재현한 평가가 아니라, **같은 가중치로 다른 문제에서의 전이를 검사한 평가**다. 487과 470을 서로 다른 가중치의 점수나 같은 900개 반복 점수로 해석하지 않는다.

보존·재현의 기준 모델은 기존 validation에서 487점을 기록한 `strict_auto` LoRA다. 어댑터 SHA256은 `90f0afaf72f22c622fd7e533514b02efd0b650d07589ff5773f6864b952188f8`이며, 실제 144개 텐서와 병합 가중치 해시가 앞선 검증과 일치했다. 이번에는 **추가 학습 0회**, 가중치·프롬프트·예산의 사후 선택도 없었다.

## 새 900문항을 어떻게 골랐는가

- [고정 공식 MMMU test](https://huggingface.co/datasets/MMMU/MMMU/tree/98e6ac0cb9b7b2cd2c991b85a50762edc4aedc68)의 10,500개에서 30분야×30개를 선정했다. 공식 test 전체나 리더보드 점수가 아닌 분야 균형 표본이다.
- 분야 안에서 `SHA256(unseen-v1:3407:<ID>)` 순으로, 사전에 정한 입력 검사에 통과한 첫 30개를 선택했다. 선정에 정답·모델 출력을 사용하지 않았고, 선정한 뒤 이미 공개돼 있던 [고정 공식 정답](https://github.com/MMMU-Benchmark/MMMU/blob/b26bdefc7e5e007962fde8f93b2bb53c99c8d13d/mmmu/answer_dict_test.json)의 `ground_truth`를 그대로 사용했다.
- 기존 validation 900의 질문·959개 고유 RGB 이미지와 실제 합성 학습 48개를 대조했다. 정규화 질문 동일/문자 3gram Dice≥0.92와 길이비, RGB 동일/유사 종횡비의 dHash≤4를 적용했다. 기존 질문 유사 61개·기존 이미지 유사 56개·선정 내 질문 유사 27개를 제외했고, 최종 표본은 이 검사에서 중복 0건이었다.
- 과거 프로젝트 결과 기록에서 이 test ID를 사용한 이력을 발견하지 못했다. 의미상 모든 변형 중복과 Qwen 사전학습 포함 여부를 배제한 것은 아니므로 **프로젝트 미사용 표본**이라고 부른다.
- 객관식 849·주관식 51개다. 이미지 항목은 1,036개, 원본 바이트 기준 고유 이미지 1,004개이며 31개 이미지가 표본 안에서 재사용된다. 이전 평가/학습 자료와의 중복 0건과 새 표본 내부의 이미지 재사용을 혼동하지 않는다.

## 실제 평가 조건

원본 `Qwen/Qwen3-VL-4B-Instruct` revision `ebb281ec70b05090aa6165b016eac8ec08e71b17`, L4/BF16, Python 3.12.3·torch 2.8.0+cu128·transformers 4.57.1·peft 0.17.1·vLLM 0.11.0·qwen-vl-utils 0.0.14를 사용했다. P0, 원래 이미지 전처리(min_pixels 1,003,520/max_pixels 4,014,080), 최대 2,048토큰, engine seed 3407와 기존 문항별 SHA256 seed, MP0를 유지했다. temperature 0.7/top_p 0.8/top_k 20/repetition_penalty 1.0/presence_penalty 1.5다.

실제 요청창은 24개, max_num_seqs 8, context 12,288이며 표본의 최대 이미지 수는 5개다. 두 arm에서 같은 입력과 묶음 규칙을 사용했다. arm별 새 프로세스에서 문항당 자유 생성 1회이며, 합성 학습용 소계나 기준 정답·교정 초안을 추가하지 않았고, 강제 마무리·재호출·정답 필터도 사용하지 않았다. 기준 정답은 생성 후 V8 채점에만 사용했다. vLLM 0.11.0은 BATCH_INVARIANT 미지원이며 전체 배치 불변성이나 다른 프로세스의 모든 수치 일치를 주장하지 않는다.

첫 준비 시도는 잔여 코드 조건문 오류로 **첫 생성 전, 응답 0개**에서 끝났다. 해당 두 줄을 제거하고 양 arm의 제어 흐름을 모의 검증한 뒤 같은 선정·가중치·프로토콜로 실행했다. 이 수정에 test 응답을 사용하거나 표본을 다시 고르지 않았다. 실패 기록도 보존했다.

## 학습 자료와 누수·힌트의 한계

실제 학습은 별도 합성 48개의 마무리+EOS만 감독한 SFT였다. **합성 표에 정확한 소계가 이미 인쇄되고 초안에도 올바른 소계가 들어 있는 자료**라서, 처음부터 도면을 읽고 모든 관계를 해결하는 훈련과 같다고 설명하면 안 된다. 마무리 산술의 검산과 초안 전체의 타당성 검증도 다르다. [팀 문서의 소계·편향 설명](training_final_20261118.md)을 함께 읽는다.

직접적인 MMMU 정답 학습/평가 입력 누수, 힌트가 풍부한 합성 자료의 한계, 기존 validation 반복 분석에 따른 방법 선택 편향은 서로 다른 문제다. 이 실험은 기록상 직접 누수를 확인하지 못했으나 모든 오염이나 편향이 없다는 인증이 아니다. 새 표본도 공개된 같은 MMMU 벤치마크이므로 다른 벤치마크로의 일반화까지 검증한 것은 아니다. 이후 이 test 900의 결과를 보며 조건을 바꾸면 다음 실험에서 미사용 최종 표본으로 부를 수 없다.

## 결과 검증·보존·시간

두 arm 각각 900개 고유 ID, 동일 입력/실제 prompt token 해시/문항 seed, 누락·중복·오류 0을 확인했다. 원격 별도 비교와 로컬의 같은 고정 V8로 1,800개 저장 응답을 재채점해 채점 필드가 모두 일치했다. 모든 17개 증분 ZIP과 실제 ready marker를 순서대로 보존하고, Drive 업로드 후 실제 회수 바이트·전체 SHA256·CRC·내부 모든 파일 SHA를 검사했다. 최종 121개 artifact의 최신 해시와 이전 16개 marker의 연속성, 마지막 marker의 별도 왕복 검증도 통과했다. 마지막 ZIP만으로 전체를 복구할 수 없다.
