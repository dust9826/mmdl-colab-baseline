## 결론과 비교

2,048토큰 제한은 생성량과 비용을 크게 줄였지만, 기존 32,768 실험보다 정답이 **85개 감소(-9.44%p)**했습니다. 이번 한 번의 실행에서는 비용을 줄이는 대신 정확도를 포기하는 선택이었습니다.

|---|---:|---:|
| 평가 문항 | 900 | 900 |
| 정답 / 정확도 | 564 / 62.67% | 479 / 53.22% |
| 총 생성 토큰 | 3,836,776 | 780,211 |
| 생성 상한에 도달한 응답 | 81 (`length` 기록) | 223 (토큰 수가 2,048인 로그) |

생성 토큰은 **79.66% 감소**했습니다. 기존 시간은 중단·복구까지 포함한 경과 시간이라 새 실행 시간과 나누어 순수 GPU 속도 개선 배수로 해석할 수 없습니다. 기존 81개는 저장된 종료 사유 기준이고, 새 223개는 토큰 상한 도달 수라 집계 기준도 구별해야 합니다.

CU는 잔액 관측치입니다. 이번 세션 50.50 → 41.52 CU, 앞선 실패 준비까지 포함하면 50.71 → 41.52 CU입니다. 설치·검증·백업 등도 포함하며, 반올림된 잔액 차이이므로 별도 청구 내역을 검증한 값은 아닙니다.

## 왜 점수가 내려갔나

900개 생성 로그 중 **223개(24.78%)가 2,048토큰 상한**에 도달했습니다. 답을 내기 전에 설명이 잘리거나 최종 답 표시가 사라져 오답 또는 파싱 실패가 늘었을 가능성이 있습니다. 다만 원문과 문항별 판정 비교가 남아 있어, 이 223개를 모두 오답이나 NO_PARSE로 단정하지 않습니다.

Art Theory 26/30, Public Health 25/30에 비해 Music 3/30, Architecture and Engineering·Mechanical Engineering 각 5/30으로 과목별 차이가 큽니다. 문제 난도·시각 정보 해석·답변 길이가 함께 작용할 수 있으며, 과목별 결과만으로 원인을 분리할 수는 없습니다.

기존 응답을 2,048토큰에서 잘라 채점한 [사후 분석](token_budget_v8.md)은 485/900(53.89%), **이번 실제 새 생성은 479/900(53.22%)**입니다. 사후 자르기와 새 추론은 같지 않습니다. 문항별 seed를 유지하더라도 샘플링과 연속 배치 실행으로 응답이 동일하다고 보장할 수 없습니다. 차이 6개를 토큰 상한의 효과만으로 설명하지 않습니다.

## 어떻게 평가했나

1. MMMU validation의 900문항을 고정 모델·프롬프트로 새로 생성했습니다. `max_new_tokens=2048`은 모델 생성 단계의 상한입니다.
2. 저장된 원문을 **team-final-answer-v8** 파서가 읽어 채점할 답을 추출하고, 문제의 정답과 비교했습니다. V8은 팀 파서의 버전 이름입니다. 파서는 생성 토큰 수를 제한하지 않습니다.

4. 같은 원문을 별도 V8 재채점 결과로 저장한 뒤 검증했습니다. 479/900으로 같고 판정 변경은 0개였습니다. 이는 같은 채점 구현의 재현성 확인이며, 정답 추출 규칙 자체가 완벽하다는 증명은 아닙니다.
