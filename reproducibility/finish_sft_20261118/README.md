## 결과를 어떻게 설명할 것인가

같은 자료·시드로 다시 학습해도 최종 LoRA 텐서는 0/144개만 동일했다. 같은 가중치의 반복 추론 원문·토큰·종료 사유 일치는 원본 24/24, SFT-A 24/24였고, 서로 재학습한 A/B는 4/24였다. A/B의 최종 추출 답변은21/24, 정오는23/24가 일치했다.

시드 고정은 유지했지만 **기존 학습 경로의 비트 단위 재현은 확인하지 못했다.** 이번 동일 가중치 반복 검사에서 관측한 일치/불일치 범위와 재학습 변동을 구분해야 한다. 전체900개, 다른 요청 묶음·순서·GPU·드라이버·버전까지 같은 결과라는 보장은 아니다. 두 학습과 한 시드는 여러 시드 성능 분산을 추정하지 못한다.

기존493/900은 한 번의 실행에서 관측한 결과로 남긴다. 이번24개 점수는 이를 재현한900개 점수도, 더 나은 모델을 고른 근거도 아니다. 두 어댑터 모두 보존했으며 점수가 좋은 실행만 선택하지 않았다.

다음 검증이 필요하다면 **결정적 연산/attention 경로를 별도 조건으로 고정한 학습 반복**과 **고정된 가중치의 전체900 반복**을 분리하는 것이 우선이다. 이번 작업에서는 추가 GPU·다른 시드·전체900 재평가를 시작하지 않았다.

## 파일과 재현 방법

- `reproduce.py`: 기존 학습 함수 호출, 계측, 새 프로세스 추론5회, 독립V8 비교.
- `frozen_bundle.zip`: 자체 합성48개와 이미지·원래 token IDs·보조 코드·잠금 정보. **공개 MMMU 질문/보기/정답/원본 이미지·가중치·인증정보를 넣지 않았다.**
- `Finish_SFT_repro_L4.ipynb`: 실제 R3 실행의 출력 없는 템플릿. 수동 학습자료 업로드나 Colab Drive 인증 없이 시작하며, 모델/평가자료는 공식 고정 revision에서 받는다.
- `recover_checkpoint.py`: 사이드바에서 보존한 출력 텍스트를 ZIP으로 복구하고 SHA256·CRC·파일 목록·개별 해시·안전한 경로를 검사한다.
- `README.md`: 이 실행 조건·결과·한계.

자료/산술 검사는 GPU 없이 실행할 수 있다.

```bash
python3 reproduce.py audit frozen_bundle.zip
```

L4 노트북을 새 세션에서 한 번만 실행한다. 중간 체크포인트가 나오면 표시 텍스트를 보존하고 다음처럼 복구한다.

```bash
python3 recover_checkpoint.py checkpoint-000001-visible.txt checkpoints
```

복구 ZIP을 자기 Drive에 저장하고 다시 받아 전체 SHA256·CRC·내부 파일 SHA256을 확인한 후, ready marker를 보존하고 해당 **실제 Drive ZIP파일ID:SHA256**을 노트북 입력란에 넣는다.4회 모두 이 절차가 필요하다. 노트북은 외부 검증 입력을 기다리며, 입력 문자열만으로 Drive 검증을 스스로 실행하는 코드는 아니다. 검증 없이 확인값을 입력하면 안 된다.10분 동안 확인이 없거나 계산 제한2시간을 넘으면 자동 해제를 요청한다. 완료/실패 시에도 자동 해제하되 실제 활성 세션0을 별도로 확인한다. 완료된 셀이나 기존 경로를 자동 재시도하지 않는다.

로컬 사전 검증은 묶음59개 구성 파일·원본48개 자료/이미지 해시·산술/토큰 구간·손상/경로 이탈 거부·노트북 내장 소스/묶음 일치·소스 문법을 확인했다. 복구 도구는 실제 생산 형식의 정상/손상 출력 및 경로·크기 제한 검사를 통과했다. 실제 실행 후에는4개 ZIP/ready 왕복, 실제144개 텐서,120개 응답/고정V8를 검사했다.
